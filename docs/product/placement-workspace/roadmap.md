# Placement Workspace — Version Roadmap

**Rule:** roadmap defines scopes and gates; it does not authorize implementation automatically.

| Version | Scope | Increment | Result | Status | Gate |
|---|:---:|---|---|---|---|
| V0.1 | A | **Full discovery demo** | Current end-to-end broker application | `DEMO_READY` | Coherent demo clearly marked hypothesis/synthetic workflow. |
| V0.2 | B | **Real placement reconstruction** | Rebuild one complex placement from real intake→submission→questions | `PROPOSED_NEXT` | Broker confirms pains, repeated questions and artifacts. |
| V0.3 | B | **Submission Domain Contract** | Submission/Version/Question/Response/Market candidates | `PROPOSED` | Objects recur and ownership is clear. |
| V0.4 | B | **Technical Pack Builder** | Assemble versioned submission from shared technical truth | `PROPOSED` | Real placement reduces reconstruction without invented facts. |
| V0.5 | B | **Missing Information workflow** | Track client requests to source facts/evidence | `PROPOSED` | Broker operates a real request loop. |
| V0.6 | B | **Market Q&A** | Question→evidence-backed response→human approval | `PROPOSED` | Real market questions handled with provenance. |
| V0.7 | B | **Renewal Change Summary** | Compare prior submission to current deployed truth | `PROPOSED` | Real renewal validates material-change workflow. |

| V0.9 | C | **Broker integrations** | CRM/document/email integration only for repeated pain | `DEFERRED` | Repeated manual source-system friction. |
