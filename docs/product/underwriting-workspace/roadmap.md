# Underwriting Workspace — Version Roadmap

**Rule:** roadmap defines scopes and gates; it does not authorize implementation automatically.

| Version | Scope | Increment | Result | Status | Gate |
|---|:---:|---|---|---|---|
| V0.1 | A | **Underwriting lens** | Concept view over shared deployment truth | `CONCEPT_PROTOTYPE` | No implied underwriting recommendation. |
| V0.2 | B | **Real underwriting case** | Reconstruct one robotics/autonomy underwriting file | `PROPOSED_NEXT` | Identify decision-changing inputs, questions and authority. |
| V0.3 | B | **Underwriting Domain Contract** | Case/Question/Condition/Referral/Decision candidates | `PROPOSED` | Matches real file lifecycle. |
| V0.4 | B | **Exposure mapping** | Map submission claims to actual deployments/config/evidence | `PROPOSED` | Discrepancies and unknowns surfaced without risk score. |
| V0.5 | B | **Underwriter workbench** | Case view, questions, evidence and unresolved conditions | `PROPOSED` | One case reviewed end-to-end. |
| V0.6 | B | **Human decision persistence** | Record named decision/conditions/referral with immutable context | `PROPOSED` | No decision generated by Elaris. |
| V0.7 | B | **Material-change re-review** | Changes after review trigger human attention | `PROPOSED` | Real material-change case validates triggers. |
| V0.8 | B | **Renewal comparison** | Prior reviewed exposure vs current truth | `PROPOSED` | Real renewal demonstrates value. |
| V0.9 | C | **Portfolio handoff** | Normalized fields feed portfolio only when authorized | `PROPOSED` | Data governance and taxonomy accepted. |
| V1.0 | C | **Paid Underwriting Workspace** | Repeatable human-decision workflow | `VISION` | Paid insurer/MGA + repeated cases. |
| V1.5 | C | **Outcome-informed underwriting support** | Governed trends only, no opaque risk score | `RESEARCH_ONLY` | Sufficient outcomes and model governance. |

**Result:** Concept view over shared deployment truth  
**Status:** `CONCEPT_PROTOTYPE`

## Stop rule
If a gate fails, mark the version BLOCKED/MODIFY/MERGE/KILL rather than advancing numerically.
