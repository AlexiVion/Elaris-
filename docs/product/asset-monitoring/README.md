# Asset Monitoring

**Product status:** `HYPOTHESIS · SPEC ONLY`  
**Primary actor:** [A17](../../industry/archetypes/finance-leasing.md)

## Core decision
> What exact Physical AI asset do we finance/own, where is it deployed, what technical/service events occurred, and which events deserve a human continuity/value review?

## Triggers
- origination/acquisition
- deployment
- material technical change
- service/failure
- incident
- covenant/inspection
- remarketing/renewal

## Evidence today
No finance/leasing workflow validated. Shared asset/config/deployment/service/incident facts could support economic owners, but value/condition semantics are unknown.

## Shared Elaris truth
Organization, Robot/Asset identity, Deployment, Configuration, Change, Evidence, Service links, Incident, Audit.

## Deterministic core
Asset identity, configuration history, material-event timeline, evidence presence, deployment/service state. No valuation/credit algorithm.

## AI role
Summarize technical history and extract inspection documents. No automated asset value, impairment or credit decision.

## Human authority
Lender/lessor/economic owner humans; technical findings remain with qualified engineering/service parties.

## Horizontal leverage
Deployment Control supplies exact asset/deployment truth; Component Health/service can supply governed condition/service evidence when real and authorized.

## Boundaries
Not fleet telemetry, accounting, loan origination, valuation model, credit score or repossession workflow.
