# Humandroid — Success Criteria

## What success means

The pilot is not validated because Humandroid says “I like it”.

It is validated if Elaris improves a real recurring workflow.

## Must-have

- [ ] Humandroid selects a real deployment.
- [ ] We reconstruct the configuration without inventing critical facts.
- [ ] We link real evidence to deployment/configuration.
- [ ] We surface gaps or relationships that otherwise require manual work.
- [ ] A change produces a useful, reviewable Change Impact.
- [ ] Humandroid sees value in keeping the deployment record current.

## Strong signals

- an output is used with a customer or internal team;
- Humandroid asks to repeat it for another robot/deployment;
- Humandroid provides more data to maintain the record;
- measurable time/rework is reduced;
- Humandroid asks for a real integration;
- Humandroid asks about price/continuity;
- a paid continuation or budget appears.

## Metrics to capture

Do not invent target numbers before seeing the workflow.

Measure:
1. time to reconstruct the deployment today;
2. number of sources/people needed;
3. evidence reused in 2+ outputs;
4. time to produce a second output;
5. change-impact suggestions confirmed vs discarded;
6. time to update after a configuration change;
7. actual willingness to repeat/pay.

## Continue

Continue/productize when there is:
- recurring pain;
- real evidence reuse;
- meaningful change-management work;
- operational utility;
- repetition or budget.

## Modify

Change the wedge if:
- the pain is real but concentrated elsewhere;
- Deployment Control is too broad;
- one output captures most of the value.

## Kill / do not scale

Do not build a horizontal platform if:
- Humandroid already solves this cheaply/easily;
- workflows share little reusable data;
- changes do not create meaningful review work;
- maintaining Elaris costs more than reconstructing manually;
- there is no owner/budget;
- only conceptual enthusiasm appears.

## Final pilot question

> **Would Humandroid want Elaris to become the normal way it maintains and reuses the truth of its deployments?**
