# Elaris — Canonical Product Planning Method

## Five independent axes
| Axis | Progression |
|---|---|
| Product evidence | HYPOTHESIS → SPECIFIED → CONCEPT PROTOTYPE → DEMO READY → PILOT → VALIDATED → PAID |
| Engineering | NOT_STARTED → IN_PROGRESS → IMPLEMENTED → VERIFIED_LOCAL → RELEASED |
| Data/evidence | SYNTHETIC → REAL_ARTIFACT → OBSERVED_CASE → REPEATED_CASES → OUTCOME_LABELED |
| Authority/data use | NOT_APPROVED → INTERNAL_APPROVED → PARTNER_APPROVED → EXTERNAL_DELIVERY_APPROVED |
| Commercial | NO_SIGNAL → INTERVIEWED → PILOT_REQUESTED → PILOT_RUNNING → PAID → RENEWED |

## Version lifecycle
`IDEA → DRAFT → APPROVED_FOR_IMPLEMENTATION → IN_PROGRESS → IMPLEMENTED → VERIFIED_LOCAL → READY_FOR_FIELD/REVIEW_READY → APPROVED_BY_OWNER → RELEASED`

Alternatives: BLOCKED, DEFERRED, SUPERSEDED, CANCELLED, RESEARCH_ONLY.

## Common maturity
M0 thesis/synthetic; M1 real actor+artifact; M2 reproducible contract; M3 workbench+deterministic core; M4 human-reviewed output; M5 repeated process; M6 secure pilot+economic signal; M7 repeatable paid; M8 multi-org/system; M9 governed outcome intelligence optional.

## Mandatory pack
Every product has `README.md`, `roadmap.md`, `version-registry.md`, `execution-backlog.md`.

## Scopes
- **A:** current assets/offline.
- **B:** requires real actor/case/artifact.
- **C:** repeated cases/data/commercial scale.

## Per-version gate
Declare input, output, deterministic/AI role, human authority, non-claims, verification, data/export state and next evidence.

## GO / MODIFY / PAUSE / KILL / MERGE
GO when actor+problem+artifact+authority+output+value are real. MODIFY when workflow exists but proposed form is wrong. PAUSE for access/data/permission blockers. KILL if no gap. MERGE if it is a feature of another product.

## Persistence rule
Do not add actor-specific schema from a mockup alone. Require real actor, real artifact, recurring lifecycle, owner/authority, historical need and value.
